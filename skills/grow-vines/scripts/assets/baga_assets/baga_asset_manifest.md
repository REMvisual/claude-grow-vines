## CRITICAL findings & pitfalls (read before integrating)

- **Leaves are flat alpha cards: 8-27 polys each.** Cheap, ideal for merge-instancing.
  Budget ~10 tris/leaf.
- **Flowers are NOT uniformly cards.** Poly count ranges **24 -> 14,024**. Many flowers
  are full 3D sculpted geometry (e.g. `Vitis_vinifera_*_flower_*` = 6k-14k polys each,
  `Trachelospermum_jasminoides_flower_002/003/004` = 690-1294). A handful ARE low-poly
  cards (24-130 polys). **You MUST poly-gate flower selection** (the prototype skips any
  flower > 400 polys) or a single flower will blow your whole tri budget.
- **Fruit: 27 assets, poly counts vary** (also often 3D, treat like flowers — gate by poly).
- **Textures are PACKED but their on-disk filepath is DEAD** (`D:\Projets...` / `S:\1_PRO...`).
  - Renders fine in Blender (uses the packed blob).
  - `save()`/`reload()`/`unpack()` that touch the dead path FAIL ("Keeping packed image").
  - FBX `embed_textures` reads `image.filepath`; with a dead path it embeds NOTHING
    (FBX stays ~70 KB). **Fix used:** read `img.pixels[:]` (forces decode), copy into a
    BRAND-NEW image datablock with a clean local path, `save()` + `pack()`, swap node refs.
- **BSDF is wrapped in a node GROUP.** The FBX exporter does NOT recurse into node groups
  to collect textures, so even with valid packed images it exports zero maps. **Fix used:**
  for the FBX only, flatten each card material to a top-level Principled BSDF
  (color->Base Color, alpha->Alpha). Render uses the original rich graph; export uses the
  flattened one. After both fixes the FBX embeds correctly (~19 MB, 9 images round-tripped).
- **Baga color map is the `*_Maps` atlas**, not a file named `*_color` (heuristic must
  accept "maps"). Alpha is a separate `*_Alpha` map.
- **No `other`/broken assets** — all 354 have geometry, UVs, materials and packed textures.
- **Species naming is fragmented**: a species' leaves and flowers can land under different
  group keys (e.g. `clematis` leaves vs `clematis_flower`/`clematis_indigo` flowers, `rosa_leaf`
  vs `rosa_flower`/`rose_flower`). This is a naming artifact, not missing data — match by
  genus prefix when pairing leaves+flowers.

## Integration recipe (validated by prototype)

- **Orientation basis** per placement (card local axes: X=width, Y=length, Z=flat normal):
  - `t` = branch tangent; `out` = radial dir perpendicular to branch, spun around the
    branch axis by a **golden-angle (137.5 deg) phyllotaxis** phase per node.
  - `cardZ = out` (leaf faces outward), `cardY = normalize(out*sin(tilt) + t*cos(tilt))`
    with **tilt 35-60 deg**, then a small **roll +/-18 deg** about cardZ. Orthonormalize.
- **Scale normalization**: `scale = TARGET / max(source.dimensions)`; TARGET ~0.08 m leaves
  (range 6-12 cm), ~0.05 m flowers. Per-instance jitter 0.9-1.15.
- **Density**: one leaf node every ~4.5 cm of arc length; flower probability
  `0.18 * (0.4 + growth)` so flowers bias toward the tip. ~29 leaves + 5 flowers on a 1.85 m
  branch = 1,736 tris incl. the bark tube.
- **Growth attribute**: per-vertex vertex-color layer `growth` = node_index / (N-1),
  R=G=B=t (0 at root, 1 at tip) for wipe/grow shaders. Survives FBX round-trip as
  CORNER/BYTE_COLOR.
- **Merge**: bmesh, one face per source poly, copy the card's own UVs into `UVMap`,
  `material_index` from a dedup'd slot list (leaf mat, flower mat(s), bark). `remove_doubles`
  at 1e-5. Guard against cards with no UV / no material.
- **Export**: flatten materials (above), `export_scene.fbx(path_mode='COPY',
  embed_textures=True, colors_type='SRGB', mesh_smooth_type='FACE')`.
